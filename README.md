# firmware-take-home

Each proposed solution contains is own README file to better document each application.

Never the less, the following applies to both:

- commit messages: conventional commits

  - **why**: make messages usefull for automatic tools to generate versions

- development language for coding: C

  - **why**: I'm most confortable at developing C at the moment.

- development language for documentation: english

  - **why**: keep the source code and its documentation in the same language.

- development strategy: feature branches with squashed PRs linked to issues

  - **why**: make traceability explicit for each problem without sacrificing main cleaness

As the solutions were proposed in C, many Objected Oriented expressions used along the documentation refer to their equivalents withing the capabilities of C.

AI usage is described per solution to give a better understanding of the contributions.
